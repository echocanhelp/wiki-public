Echopedia System Architecture

Human → Planner → Worker → Git → Telegram flow

Planner (default profile)

  • • Model: Grok → NVFP4 (sticky)
  • • Role: Architecture design, user-facing chat
  • • Assigns work via kanban assign
  • • Plans in ~/.hermes/plans/

Worker (pinto profile)

  • • Model: NVFP4 only
  • • Role: Kanban execution, bounded work
  • • Runs WORKER.md playbooks
  • • Commits to echo-system repo

Delivery Flow

  • • Worker → Telegram (review gate)
  • • Human → Planner (reply)
  • • Git → shared artifact store
  • • Kanban → dynamic work graph
