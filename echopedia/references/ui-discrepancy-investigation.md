# UI Discrepancy Investigation Pattern

When the user reports content that doesn't match the repo (e.g., "wrong summary on Featured People"), follow this order:

## Step 1: Verify Actual UI State
**Always hard-refresh the live page first.** Check:
- `curl -sI https://echocanhelp.github.io/wiki-public/` → check `Cache-Control`, `age` headers
- Hard-refresh the browser (Ctrl+Shift+R / Cmd+Shift+R)
- Inspect the rendered HTML for the reported section

## Step 2: Check Root index.html (CRITICAL — Most Common Source)
**GitHub Pages serves the repo root `index.html` as the homepage.** This is the #1 source of stale content. The root `index.html` is a **static HTML file** (not auto-generated by Quartz) and may contain hardcoded sections like "Featured People" cards.

**Check:**
```bash
# Search root index.html for the reported text
grep -n "REPORTED_TEXT" /home/leedt/echo-system/index.html
```

**If found:** This is the source-of-truth for the homepage. Patch it directly, commit, and push.

**Why this trips us:** The `public/` directory has its own `index.html` (from Quartz), but GitHub Pages serves the **root** `index.html`. They are different files. The root file is static and hand-maintained; the `public/` file is auto-generated.

## Step 3: Check Auto-Generated Sources
The Echopedia homepage is **auto-generated**, NOT a custom page:
- Source: `content/.wiki-index.md` (auto-generated by `scripts/echopedia_index.py`)
- Output: `public/index.html` (Quartz renders this as the home page)
- There is **no** `content/index.md` — the home page IS the index file rendered by Quartz
- The index lists pages by type (people, organizations, etc.) — no "Featured" section exists

## Step 4: Search Content Tree
Only after confirming what the user actually sees:
- `grep -ri "featured" content/` (case-insensitive)
- `grep -ri "featured" scripts/` (check index generator)
- `grep -ri "featured" public/` (check built HTML)
- Check Quartz config for chrome-level features

## Step 5: Check contentIndex.json (Client-Side Rendering)
Quartz renders the homepage "Featured People" section **client-side** from `public/static/contentIndex.json`. The JSON can be stale even when source `.md` files are correct.

**Check:**
```bash
# Look at what the deployed site is actually serving
grep -o '"content":"[^"]*"' public/static/contentIndex.json | grep -i "physician\|lai" | head -5
# Or for a specific slug:
python3 -c "
import json
with open('public/static/contentIndex.json') as f:
    data = json.load(f)
print(data.get('people/albert-s-lai', {}).get('content', '')[:500])
"
```

**If the JSON has the wrong text but the `.md` source is correct:** The site needs a rebuild + redeploy. The stale `contentIndex.json` was baked into the old build output.

**Fix:** Rebuild with Quartz, copy output to gh-pages tree, commit + push.

## Step 6: Consider External Factors
If nothing found in content tree or contentIndex.json:
- CDN/GitHub Pages cache (stale HTML from before a rebuild)
- Browser cache (user may be looking at old cached page)
- Different URL or section the user is referencing

## Key Operational Facts
- **Root `index.html`** = static homepage served by GitHub Pages (source of truth for homepage UI)
- **`public/index.html`** = auto-generated by Quartz (NOT served as homepage)
- **`public/static/contentIndex.json`** = client-side data source for dynamic sections
- Index last regenerated: 2026-07-13 (may be stale — counts lag post-TC)
- No custom `content/index.md` exists
- No "Featured People" section in the content tree
- The Albert Lai entry in the index is an auto-generated directory listing, not a curated blurb

## Pitfalls
- **Do NOT** search for a "Featured" section that doesn't exist in the content tree. The user may be looking at the root `index.html` (static), a cached page, or the auto-generated index.
- **Root `index.html` is NOT auto-generated.** It's a static file that must be patched directly. Do not assume it will be regenerated by Quartz.
- **Two different `index.html` files exist:** root (static, served) and `public/index.html` (auto-generated, not served). Always check both.
