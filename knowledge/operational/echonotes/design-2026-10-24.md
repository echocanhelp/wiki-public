# EchoNotes — MeetNotes → Echopedia-native meeting memory (design draft)

**Date:** 2026-10-24 · **Status:** SUPERSEDED by PLAN v2 → `~/.hermes/plans/2026-10-24_135241-echonotes.md` (Grok-verified) · **Asked by:** Leonard (EchoNotes group)
**One-liner:** Turn MeetNotes (local AI notetaker) into EchoNotes — a social intake surface where every recorded meeting becomes primary-source Echopedia material: speaker-identified, entity-linked, publicly publishable, and it surfaces high-value exploration leads back into the nightly pipeline.

---

## 1. MeetNotes as-is (verified against code, 2026-10-24)

Repo `~/code/meetnotes` (~1,843 LOC). DB `data/meetnotes.db`: **16 meetings, 1,627 utterances, 6 enrolled voices** (Leonard, Phoenix, BoardMember, AuditBoss, Stephen, Junior), tenant `hsu-family` only.

| Module | What it does | EchoNotes relevance |

## 2. Echopedia purpose (why EchoNotes fits)

From `SCHEMA.md` + `echopedia/WHERE_WE_ARE.md`:
- **Living archive, not news agency** (CONTROL §1b): get personal, never withhold high-value info; the guardrail is *labeling + attribution*, not omission. A recorded conversation is the **highest-quality primary source the vault can get** — richer than web harvest.
- Tier 2 (`knowledge/`) is private capture; Tier 1 (`content/`) is curated public. Promotion needs the ingest protocol, never automatic.
- Nightly deterministic pipeline already does deepening: quote-extractor, timeline-builder, person-works-linker, janitor, NEED YOU queue.
- Existing discipline to reuse verbatim: identity close-loop (HOLD on conflict, never auto-merge), `new_hold` for consent-without-slug, **no auto-create pages**, health redaction, packs capped (EE lesson: a 26–37k pack blew the LINE token budget).

## 3. Gap analysis (MeetNotes → EchoNotes)

1. **Speakers ≠ people.** Voiceprint names are free-text per tenant; no link to `content/people/<slug>`.
2. **No entity linking.** Transcript never runs through `echopedia-first-answer.py` / `echopedia-bm25-search.py`; zero wikilinks minted.
3. **No event pages.** The meeting itself is a community event (who/when/where/what) — should mint an `events/` page.
4. **No exploration hints.** Vault-intelligence collectors (`vault-connector-suggestions.py`, `vault-unfinished-threads.py`) exist but never see meeting text.
5. **No social intake.** Single tenant, no LINE upload path, no contributor/consent metadata.
6. **LLM is context-blind.** `extract.py` doesn't know who's in the room or what the linked pages already say — so it can't spot gaps or conflicts.
7. **Publishing is manual one-off** (`mint_echopedia.py` args), no ledger of meeting → published slug.

## 4. EchoNotes pipeline (stages; ★ = new, rest exists)

```
INTAKE (any of)
  A. LINE upload video/audio (contributor or household)      ★
  B. bot.py joins Teams/Meet link
  C. webapp :8130 upload (.mp4/.m4a/.wav)
        │  metadata: title, date, location, contributor, consent tier
        ▼
MEDIA ENGINE (unchanged)
  silence gate → Breeze STT → pyannote diarize → CAM++ voiceprint
        ▼
★ IDENTITY RESOLUTION  (the keystone)
  new table voice_identities(tenant, profile_name, person_slug, status, score)
  - voiceprint matches an ENROLLED profile whose person_slug is CONFIRMED
      → label speaker as that Echopedia person
  - unknown voice / thin margin → "Speaker N", drop a 🔴 NEED YOU
      identity card (reuse identity close-loop pattern)
  - NEVER auto-link an unconfirmed voice to a person page
        ▼
★ ENTITY LINKING (deterministic first, LLM last)
  mentions → echopedia-first-answer / bm25 search
  HIT  → wikilink [[people/slug|Label]] (+ org/event), record in meeting_entities
  MISS + high-value (repeated mention, 漢名, role words)
      → new_hold stub (knowledge/…/echonotes/holds.jsonl) — no auto-create
        ▼
★ ECHOPEDIA-GROUNDED ANALYSIS (:8888 worker, capped pack like EE)
  prompt = transcript + dossier pack of linked pages (cap: 4 dossiers, ~14k chars)
  output = summary / decisions / action items / topics            (exists)
         + people_deepen: facts that fill gaps on linked pages
           (dates, roles, places — each with transcript timestamp)
         + quotes: quotable lines → feed quote-extractor corpus
         + timeline_entries → feed timeline-builder
         + page_conflicts: teller beats page → HOLD, flag, never overwrite
         + exploration_hints: unlinked names, missing pages, suggested
           interviews ("Uncle Jeff mentioned 5×, no page — capture sitting?")
        ▼
ARTIFACTS
  Tier 2 (always, private): full transcript + analysis in vault + sqlite,
    audio in LAN archive, provenance chain page → meeting_id → wav → mm:ss
  Tier 1 (owner GO, like today's mint):
    - topics/<slug>.md meeting record (generalized mint_echopedia)
    - P8-style deepens on linked person pages, source note
      "EchoNotes meeting YYYY-MM-DD (audio transcript, speaker X)"
    - events/ page for the meeting
  publish ledger: meeting_links(meeting_id, slug, published_at)
```

Everything lands in the **one vault** (`echo-system/`) — no second wiki (SCHEMA rule).

## 5. The multiplier (social contribution loop)

- TAHS/church members record gatherings (座談會, 同學會, church events, oral-history sittings) and upload via LINE; EchoNotes does the boring 90% (transcribe, diarize, link, draft).
- **Compounding voiceprint registry:** every meeting enrolled improves recognition for every future meeting, per tenant.
- **Each meeting multiplies:** 1 meeting → 1 event page + N person deepens + quotes + timeline rows + a queue of exploration leads → those leads become janitor/NEED YOU items → next week's deepening work is *generated by the community's own conversations*.
- **Consent ladder** (per upload, default lowest): private (household) → community (TAHS members) → public (site). Public mirrors today's rule: owner-directed, health-redacted, `primary-source` labeled.
- Contributor credit line on minted pages ("recorded by …, with EchoNotes").

## 8. Risks & guardrails

- **Identity misattribution = the big one.** A wrong quote under a real elder's name is reputational. Rule: publish attributed speech only from CONFIRMED voiceprints; everything else stays "Speaker N" or private.
- **Hallucination:** Tier 1 text is transcript-derived only; analysis sections are clearly labeled AI summary; `verification_status: primary-source (audio transcript)`; hints are leads, never content.
- **Privacy:** health redaction exists (wordlist) — extend per household/community policy; audio never leaves LAN; consent tier gates publication; U-ids never surface.
- **zh/taigi code-switch ASR + diarization:** keep silence gate, margin rule; low-confidence utterances flagged, not silently published.
- **Token economy:** deterministic linking first, one LLM pass at `:8888` (LAN), pack caps (EE 95k-token incident is the cautionary tale).
- **No parallel systems:** EchoNotes = MeetNotes + Echopedia hooks, not a new app; EE (1-on-1 sittings) and EchoNotes (group meetings) stay separate OAs, share the vault.
