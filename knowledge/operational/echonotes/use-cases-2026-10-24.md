## UC-1 — "We're at a meeting, 4 people, I hit record"

Flow:
1. PWA (or any recorder — **upload-later is the primary path**, confirmed direction) → New meeting card: title, date, location, expected attendees (priors only), consent tier, tenant.
2. Record on device → upload when done. **Complete-file sha256 must exist before a job, GPU lock, or :8888 call is spent.** Chunked upload; chunk expiry is a non-event (no partial job).
3. **Deterministic preflight runs first, no LLM:** decode, container duration vs decoded duration, abrupt-cut check, speech-vs-silence. Recorder died mid-meeting → `status=partial`: no vault write, no centroid update. Failed quality → skip LLM, owner-visible reject reason.
4. Ack = one free Reply; terminal push when draft ready.

Rules (Grok-folded):
- **Consent subject = owner uid + explicit `consent=public` attestation**, stored. Not tenant-wide. Another household uploader, allow-listed contributor, non-attendee uploader, or pre-picks outside tenant → forced private draft + one owner push. Missing consent = private even if the card preselected public. Tenant comes from the token, not the form. A forwarded Zoom never clears the gate on attestation alone.
- Pre-picks are **priors, not links** — they raise HIT ranking only.
- LINE oversize = reject with PWA/file instruction (not resumable via LINE).

## UC-2 — "Tag speakers to Echopedia pages or events"

- Auto-label only: cluster clears publish-attribution bar (≥0.55 / margin ≥0.15 / min voiced seconds / low variance — **thresholds to be re-measured on the existing 16 meetings as phone-audio FAR/FRR, not inherited from clean-speech numbers**) AND profile `status=confirmed`.
- **1:1 assignment:** clusters↔profiles matched one-to-one. A second cluster clearing 0.55/0.15 against the same profile stays Speaker N. Two clusters → one slug only via explicit merge, and only when their mutual cosine says same voice; no auto-merge on phone audio until measured.
- **One tap = `claimed`: labels THIS meeting only and does NOT update the centroid.** `confirmed` (publishable attribution) = 2nd-meeting match on a **different audio fingerprint** (not a re-encode) or explicit owner confirm.
- Corrections (split/merge/reject) are stored as **constraints**, never averaged into centroids; if two profiles are both expected next time, neither is auto-named. (New table `assignment_constraints`; `learn_ground_truth.py` does not do this today.)
- Recognition memory: cluster embeddings + stats persist per tenant, never cross-tenant.
- Introduction cues (我叫/我姓/"I'm…"/spelling-bee/Dr.+name) are suggestions; **their absence is the normal case, not a failed job.**

## UC-3 — "Summary published automatically; related pages updated automatically"

**OWNER POLICY 2026-10-24 (supersedes Grok's hold-until-green): publish-first, fix-forward.** Auto-publish runs **immediately when the job completes — not overnight**. Unknown speakers publish as Speaker N; unlinked mentions publish as plain text; verification or a link later **queues a re-publish** instead of holding the page.
- **Publisher gate (accountability chain, owner call):** auto-publish allowed when the **uploader's LINE identity is linked to an Echopedia person page** (identity close-loop registry) + consent=public. The page carries "recorded by [[people/slug]]" — their name is on the line. Unlinked uploader → private draft + owner OK.
- **Meeting page:** mint + push right after processing, via the existing single-page detached-worktree publish path (proven with the Kanola pages). ci-heal stays the nightly drift/heal pusher, not the publish path.
- **Partial meetings publish too** (owner call): `status=partial` ships with a "partial recording" banner + covered range mm:ss; only silence-gate failures and unreadable files reject.
- **Speaker names:** page ships with Speaker N. When a voice is verified (owner tag + 2nd meeting or explicit confirm) → auto re-publish with the name. Until then no real name sits under speech.
- **Echopedia links:** mentions ship as text; when linking resolves (auto or owner tag) → queue re-publish with wikilinks. Never hold a page waiting for a link.
- **Related pages — no approval needed (owner call):** auto-update ALL linked pages with relevant high-value data (deepens, quotes, timeline rows, presence bullets). Safety = labeling, not gating: every auto-write is append-only, source-cited (`meeting_id + mm:ss`), marked machine-added, conflict → HOLD + NEED YOU, retractable. Publish first, fix later.
- **Holds that survive are PRIVACY only, never completeness:** redaction trigger count = 0 on RAW text (CJK-aware); forwarded/third-party recordings forced private; no U-id / filesystem path / Tier2-only fact in minted markdown.
- Managed section `## 來自會議紀錄 (From meeting records)` is append-only, capped, never rewrites prose.
- Hold-stubs live in **sqlite, not content/** (tier1-sweep commits any content/ drift at 00:40 — stubs there would ship).
- **Retract stays mandatory:** unstage / tombstone / centroid rollback — publish-first is only safe because mistakes are retractable.

## UC-6 — Meeting page template (historical focus + bridge links)

Public meeting page = grounded summary, spanned decisions, talk time, **cited excerpts** (not the full transcript). Full transcript + the "LAN archive replay" sentence that `mint_echopedia.py` writes today stay **Tier2**.
Sections: provenance header (credit, consent tier, redaction notice, `primary-source (audio transcript)`) · People in this meeting (confirmed only) · Entities surfaced (linked HITs; holds in sqlite) · Historical extracts (deterministic quotes/timeline/places/dates, cited `meeting_id + mm:ss`) · **Bridge links** · Exploration hints.
- **Bridge links (Grok-folded):** co-mention is not presence — store pairs in sqlite, **label mention vs presence** on the meeting page, and let the **janitor suggest** reciprocal page lines rather than auto-appending at publish. Caps: corpus-level `max_pairs_per_target=3` (the janitor explosion was across meetings, so per-meeting ≤3 alone still floods a hub), page-level cap, hub denylist.

## UC-7/8/9 — Missing UCs (Grok) — adopt as first-class

- **UC-7 Retract / bad-publish recovery:** unstage, tombstone, centroid rollback + visible NEED YOU when a green row wasn't pushed. GitHub Pages doesn't forget.
- **UC-8 Forwarded / third-party recording:** uploader ≠ only data subject. Non-attendee uploader, non-consenting attendees, partial-dictionary health talk → **forced-private path no green gate can override**.
- **UC-9 Reprocess & EE misroute:** sha256 idempotency would block "I fixed the speakers, rerun it" → need an explicit `reprocess` flag (same meeting, new analysis rows, no re-enroll). A long 2-person recording is an **EE oral history** — detect (2 voices, long duration, interview cadence) and route to EE, don't mint a meeting page.

## UC-10 — EN/中文 language toggle (owner request 2026-10-24)

Coverage reality (measured 2026-10-24, 15,264 content pages excl. articles): 13,453 EN-only · 1,657 mixed · 153 ZH-only. Key reader surfaces already carry both: people 1,200/2,457 mixed, organizations 190/440, topics 65/79. The EN-only bulk is `works/` (11,886 archive).

Design (static-site-safe, no server, no keys in JS):
1. **L1 — client-side toggle, zero content change:** build-time deterministic language tagging — each block gets `data-lang="en|zh|mix"` from a CJK-ratio classifier; a header `EN | 中` toggle (exact pattern of the existing dark-mode switch in `prescript.js`, preference in localStorage) shows the reader's language, falls back to the other where missing; `mix` blocks always show. Works today for the mixed pages.
2. **L2 — EchoNotes bilingual at birth:** the one :8888 analysis call emits summary/decisions/hints in BOTH en+zh-TW (bilingual JSON); mint renders both tagged blocks. **Transcript, quotes, and 漢名 never translate** — primary source stays as-spoken; only analysis text is bilingual.
3. **L3 — MT backfill, batch not live:** nightly deterministic cron finds pages missing a language → one :8888 translation call per page → committed as a labeled block: "機器翻譯 Machine translation — 來源 source" chip + link to original + NEED YOU review queue. Prioritized by GoatCounter traffic (`gc-path-counts.json` cache exists). People/orgs/topics first; `works/` last or on demand.
4. **Why not live browser translation:** API key in JS leaks, per-view cost, breaks static/offline, unreviewable. MT generated once, committed, labeled, retractable = fixable like everything else.
- Editorial rule: names/quotes/hanzi are inviolate; MT never replaces source text, only sits beside it.
- Applies to: EchoNotes meeting pages (L2 from day one) + all Echopedia system pages (L1 site-wide, L3 by traffic).

## Simple high-value enhancements (Grok round 3, 2026-10-24) — additive, all ride existing machinery

Verdict: `grok-verdict-r3-2026-10-24.md`. Ranked build list:
1. **Meeting-keyed upsert (S):** re-publish REPLACES that meeting's machine block (meeting page + related pages) — append-only vs human prose still holds. Without it, publish-first + re-publish queue doubles quotes/presence. Gate: machine bullets per meeting_id = 1 after two publishes.
2. **Retract on the ready push (S):** the terminal push already owed to the credited publisher carries public URL + one 收回 postback (accepted from publisher uid or owner only). No second push. Gate: publish→tombstone in minutes, not "next 08:30". **Cheapest trust win.**
3. **Thin-margin A/B clip (S):** when the matcher refuses on margin, the push carries two ~6s cuts + A/B/neither postbacks; a tap = claimed for this meeting, no centroid move. Gate: thin-margin wrong-name publishes = 0.
4. **Cross-meeting voice family (M):** unconfirmed cluster matching a prior meeting's Speaker N → family id (constraint row, not centroid, not slug); one confirm re-publishes the whole family. Gate: confirms per distinct voice.
5. **Collapse banner (S):** ≥4 attendee priors but diarization returns 1 speaker, or large unknown share → still publish with banner, HOLD presence bullets. Gate: presence bullets on collapsed jobs = 0.
6. **Citation fitness (S):** quote writes to person pages HOLD when Taigi text doesn't fit the zh-timed run or avg_logprob < floor (utterance rows already carry both); meeting page still shows text labeled with real window. Breeze-26 collapses timestamps to window start (stt.py:67) — Taigi is ~30s blocks, not word time. Gate: person-page quotes whose span lacks the quote = 0.
7. **Fail-closed marker audit (S):** extend site-design audit — every machine line must carry marker + `meeting_id+mm:ss` or page → NEED YOU, not "clean". Gate: unlabeled machine lines in built HTML = 0.
8. **Brief ordered by reads (S):** order the cap-5 brief strip by GoatCounter `gc-path-counts.json`; unread Speaker N meetings wait.
9. **Action items are claims (S):** stop publishing the LLM owner field (mint writes it today); 我來 postback opens a kanban card for the tapper's linked person. Gate: published action rows with person-name owner = 0.
10. **我的筆記 (S):** keyword → free Reply listing that uid's last 3 jobs + status + URL/ledger. Gate: repeat uploads per linked publisher.

Do NOT build yet: name hotwords via `initial_prompt` (hook is wired to the decoder but the pipeline never sets it — Breeze will hallucinate prompted names into quiet spans; fold aliases at LINK time only, keep transcript verbatim); live captions / in-call group transcript (holds the single GPU lock, breaks push budget — upload-later IS the product); second :8888 cleanup pass or auto-minted person pages for repeated unknown names (hints→janitor already covers it; also: new diarization model, vector DB, native recording, reciprocal bridge writes).
